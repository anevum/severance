# V0.3 Known Limitations and Security Boundary

1. **No real game server or client.** These tests cannot establish 1,000 concurrent users, a browser FPS, a controller implementation, production AI, network transport, latency or anti-cheat.
2. **No authenticated caller.** `actor="system"` is a trusted **offline fixture** and is not cryptographically authenticated. Never expose `World.apply` or `run_due` as a direct public API.
3. **Synthetic logical ticks.** Ticks are deterministic ordering markers. Scheduled work does not run unless a caller explicitly invokes `run_due`; no OS background scheduler, clock service or outage catch-up policy exists. A `TaskPlanned` event must be created explicitly.
4. **Healthcare simulation only.** Medical rescue deadlines, stabilization and rehabilitation are gameplay abstractions and not real clinical care advice. No HIPAA, medical consent verification, clinician licensing or patient identity system exists. Existing evidence **summaries are stored in ledger history**, so real health information must never be entered.
5. **Narrow grants.** Only `read` permission is modeled; no delegation chains, privacy-preserving archival deletion, legal guardian, coercion, role-based clinical orders or record-level encryption.
6. **Migration marker compromise.** `PRAGMA user_version` remains 2 to retain the **unmodified 85-test V0.2 baseline**, and the added V0.3 transactional revision lives in `worldstate_schema`. The metadata table is not cryptographically signed. A formal migration catalog and rollback backups are required before a production deployment.
7. **Finite staged freight.** Multi-stop convoys move at graph nodes and have ETA gates; they do not simulate continuous vehicle physics, traffic, real energy consumption, cargo spoilage, accident damage, convoy crews or realistic roads. An arbitrary destination does not yet have multi-leg automatic vehicle-return support.
8. **Trusted data integrity only.** Event hash chains detect unauthorized alterations only when checked against an independently trusted checksum, key or checkpoint. Database root admins can rewrite an entire ledger plus state in a self-consistent manner.
9. **Existing old fixture semantics.** Older V0.2 `ShipmentDispatched` and `MedicalCaseOpened` events remain frozen. They are not automatically converted into new V0.3 convoys/scheduled jobs, because doing so would break replay determinism.
10. **Server lifecycle.** The lab is local single-host SQLite with sequential transactions, not geo-distributed single-writer handoff, concurrent network admission, storage replication or disaster-recovery orchestration.
11. **Science and fiction.** No neural tissue is modeled at the genetic/procedural level. Character death remains final, and Roads stay physically closed unless a valid author-approved story event says otherwise. New local lore still requires creative review.
12. **Environment.** Tests executed under Python 3.13 here; the project's `>=3.10` declaration remains source-level intent and has not been proven across every Python version and OS.

**Next plausible development step** is authentication boundaries for a strictly local untrusted-client shim, explicit scheduling-driven progression of offline town reserves, consent tests with subject-linked records and secure storage, and migration rollback backup tests. Production game work remains on hold.
